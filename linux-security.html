Overview

Four questions, one hardened VM.

Linux systems can be exposed to security risks through weak default settings, services that are not needed, overly permissive file or directory access, and software that has not received available updates. This assessment examined an Ubuntu virtual machine running in Oracle VirtualBox and applied selected remediation steps while retaining the evidence needed for reporting.

The work was conducted locally inside the VM. Commands and terminal screenshots were retained in the project workspace under ~/linux-security-assessment, including a logs directory that forms the evidence base for the final report.

Method

From baseline to verified fixes.

A local, evidence-first process: inspect the system, decide what matters, remediate carefully and confirm the result.

01

A local, evidence-first assessment.

The work ran inside the Ubuntu VM and combined baseline inspection, configuration review, service and listener discovery, permission checks, package inventory, selected remediation and verification. Representative commands were recorded alongside the terminal output.

# representative commands

sudo lynis audit system

systemctl list-unit-files --type=service --state=enabled

sudo ss -tulpn

sudo ufw status verbose

sudo auditctl -l

apt list --upgradable

02

Four required areas shaped the review.

  • 1Weak configurations, including password aging, audit logging and firewall policy.
  • 2Unnecessary services that add installed functionality and potential attack surface.
  • 3Insecure permissions on account files, SSH files and privileged directories.
  • 4Outdated packages and the status of available updates.
03

Remediate, then verify.

Each change was paired with a command that confirms the new state, and the output was saved in the logs directory. Where the evidence did not support a firm conclusion — particularly the remaining package updates — the report records the item as pending rather than claiming success.

Guiding rule: a service being enabled does not prove it is running or vulnerable, and a Lynis suggestion is not the same as a confirmed vulnerability. Findings were reviewed in context before anything was changed.

Findings & remediation

What changed, and what it fixed.

Four areas reviewed, with the observed issue, the action taken and the verification recorded in the report.

Weak configurations

Password aging started at PASS_MAX_DAYS 99999 and PASS_MIN_DAYS 0. The local account was changed to a 90-day maximum, 1-day minimum and 7-day warning, verified with chage -l. UFW was enabled with a default deny-incoming policy, and auditd was installed with watches on /etc/passwd, /etc/shadow and /etc/sudoers.

Remediated · verified

Unnecessary services

Bluetooth, CUPS printing, CUPS-browsed printer discovery and ModemManager were not required for the VM's assessment tasks. They were disabled and stopped with systemctl disable --now, and the CUPS socket and path activation units were disabled as well. Avahi was retained for local service discovery.

Disabled · verified

Insecure permissions

Core account files were already correctly restricted, and the user's ~/.ssh directory was mode 700 with authorized_keys at 600. The /etc/sudoers.d directory was tightened from 755 to 750. World-writable directories were reviewed rather than changed indiscriminately, since /tmp and /var/tmp rely on the sticky bit.

Hardened · verified

Outdated packages

The inventory began at 146 upgradeable packages. A later APT plan selected 95 for upgrade and held back 10 because of phased updates; the final captured list still showed 10 packages. Those are recorded as pending verification rather than confirmed installed updates.

Pending · verification
Network note: a GVFS Web Services Dynamic Discovery process (/usr/bin/wsdd) was found listening on UDP ports 3702 and 50203. Process inspection traced it to gvfs-backends and the user's desktop session, so it was identified as a legitimate discovery component and retained rather than treated as malware.

A hardening index, not a guarantee.

Reading the results

Careful claims.

Suggestions included file-integrity monitoring, sysctl review, compiler-access hardening, a malware scanner and permission review. They are recommendations for additional hardening and do not automatically mean a vulnerability was confirmed.

The scan also noted that the installed Lynis release was more than six months old and that its end-of-life database had no entry for this Ubuntu release. Those notices are not proof that Ubuntu itself is end-of-life.

Interpretation

Honest reporting.

The report separates verified changes from open items. Ten packages remained upgradeable in the latest captured package check, with phased updates noted by APT, so they are recorded as pending rather than fixed.

World-writable directories such as /tmp and /var/tmp can be legitimate when protected by the sticky bit, and the GVFS WSDD listener was identified rather than removed. The conclusion recommends repeat audits, log review and a post-update Lynis scan.
