Overview

Encrypted storage with sharing you can revoke.

CipherVault lets registered users upload documents, keep them encrypted at rest and share them with specific people. Owners can grant view-only or download permission, manage those grants and revoke access at any time.

I designed and implemented the application structure, database models and interface, then built the Flask authentication, file handling, encryption and sharing workflows. The repository includes automated tests and setup documentation.

Security design

Protection across the workflow.

Four layers work together: identity, encryption, authorization and auditability.

Authentication and roles

Passwords are hashed, sessions are managed through Flask-Login, and administrator routes are restricted by role.

Identity

Encrypted files

Uploads are encrypted with AES-256-GCM before being written to storage outside the static web directory. The encryption key is supplied through environment configuration.

Confidentiality

Controlled sharing

Owners grant view-only or download access to registered users, manage permissions and revoke a grant. Authorization is checked on backend requests.

Authorization

Activity and monitoring

Activity logs and security events cover important account, file and permission actions, including failed logins and unauthorized access attempts.

Auditability

Reflection

What I built and learned.

This project brought together secure application design and full-stack development: modelling file ownership and permissions, enforcing access on the server, encrypting stored data, and recording actions for review. It also reinforced the need to test both allowed actions and denied or revoked access.
