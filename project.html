Overview

Can a model separate normal activity from a takeover?

Customer accounts can be compromised through a combination of unusual authentication events and account changes. This project explores whether supervised machine learning can separate normal activity from activity associated with account takeover.

I trained and compared three classifiers on a public risk-based authentication dataset, adjusted for severe class imbalance, and integrated the chosen model into a small Flask application that returns a prediction for submitted account activity.

Approach

From a hard question to a working model.

A supervised classification workflow built around a rare positive class, interpretable models and honest evaluation.

01

Rare takeovers, noisy signals.

Account takeover is uncommon, which makes it easy for a model to look accurate while missing the very events that matter. Only 141 of 50,141 sampled logins are takeovers — 0.28% — so balanced class weights and F1-score guide model selection rather than accuracy alone.

Key constraint: a false negative is a missed compromise, while a false positive creates unnecessary review work. The evaluation therefore reports precision, recall, F1 and ROC-AUC alongside accuracy.
02

Five objectives shaped the build.

  • 1Analyze customer account activity data.
  • 2Identify patterns associated with account takeover.

  • 4Compare the performance of different models.
  • 5Develop a Flask-based prediction system.
03

Three classifiers, compared fairly.

Each model brings a different bias to the problem, so comparing them shows which approach fits this data rather than assuming one is best.

PythonFlaskScikit-learnPandasNumPyMatplotlibJoblib

Logistic Regression

A linear model that estimates the probability that an account belongs to the compromised class. Simple, fast and interpretable, so it works well as a baseline.

Decision Tree

Splits the data with a series of if-then rules on account features. Easy to read and explain, but a single tree can overfit the training data.

Random Forest

An ensemble of decision trees that averages many weak learners. It usually generalises better than a single tree and exposes feature importance for review.

Data

A public, labelled dataset.

A public research dataset of single sign-on login attempts, labelled with a ground-truth account-takeover target.

Source

Features

Target
Is Account Takeover (0 = normal, 1 = potentially compromised)
Class balance
141 takeovers (0.28%) vs 50,000 normal logins

High-cardinality identifiers such as IP Address, User Agent String and User ID are dropped to reduce overfitting. Login Timestamp is converted into login_hour and login_day_of_week so the models can learn time-based patterns.

Because takeovers are rare, the models use balanced class weights and F1-score is the primary selection metric. Accuracy is still reported, but it is read alongside the confusion matrix and per-class scores.
